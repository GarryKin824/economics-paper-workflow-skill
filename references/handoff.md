# 交接与返修：保证每一项事实可查

## 05｜把研究完整交给 AGY 执笔

新写作者需要项目背景、分工、当前底稿、全部核定结果及原件索引。测试包内链接、附件和可访问路径。对历史问题只给原句、位置、核定事实，不替写。手工转发时分开准备事实包和任务 Prompt。

**改编示例：** 包内示例用 `00-索引.md`、冻结稿、`事实表.csv`、结果输出和原文定位；任务消息只说改哪几处、交回什么。

**可填写 Prompt**

准备材料的人使用：

~~~text
为 {{论文和投稿场合｜全题、用途及目标要求}} 准备由我手工转交给 AGY 的材料，底稿是 {{当前冻结稿｜具体附件名和版本}}；本轮任务是 {{范围｜起草或返修的内容}}。

请交一个能独立使用的 ZIP，首文件为材料索引。包括项目背景、任务分工、冻结稿、数据和变量定义、样本和分母、识别及计算方法、主要和补充结果、未获支持的结果、页码证据索引、可核原文和允许共享的复算材料。对需要调整的原表述，给出原句、页码、与客观事实的具体出入和出处。核对被指向的文件确实随包交付或对接收方可读；未附文件列明如何获取。

单独给我一段可复制的任务 Prompt，只说明底稿、索引、任务范围和交回格式。不要写示范句、行文安排或语气要求。不要代我发送。
~~~

作者转给写作者：

~~~text
这是 {{论文主题和用途｜标题、目标读者或赛事}} 的 {{当前阶段｜初稿/指定返修}}。请以 {{冻结稿｜附件名与版本}} 为底稿，先读 {{入口索引｜附件内 Markdown 路径}}，再按索引查阅客观研究事实与原始证据。

本轮任务：{{任务范围｜列出章节或待处理事实，不指定行文方式}}。请交回 {{可编辑成果｜完整稿或标注位置的替换段落}}。如已提供的材料不足以核定某个事实，请另列该问题和所需材料。
~~~

## 06｜对返稿做证据审核，不做风格评判

以实际返稿为核查对象；有作者手改时对照手改前后，不让旧日志代替差异。只报告会改变证据含义的实质问题，其余交由表达审阅或作者取舍。

**改编示例：** 统计术语用错导致任务等权和人员等权混读，应阻止合稿；作者用词自信但没有超出证据，不拦截。

**可填写 Prompt**

~~~text
审核 {{送审文件｜完整文件名、版本；必要时附页数或校验值}}，对照 {{底稿、复算包、引文原件｜说明如何打开}} 与 {{修改日志或差异｜如无则注明}}。若某处缺原数据，标为「无法核定」；区分这一状态、稿内有矛盾、已有证据支持。逐条给页码和原句、事实、证据来源、受影响范围及是否阻止合稿。只管事实与证据，不润色、不替写。最后给出「可合稿／局部修后可合稿／需退回」。
~~~

## 11｜把审稿意见变成可验收的返修任务

保留审稿原文，先核是否读对稿件，再按重要性和可行性分流。只有新增证据才开研究轮；格式、小错可定向修查。作者决定哪些暂停。

**改编示例：** 若审稿人要求比较两种名单的真实质量而档案没有验收结果，研究对话可核查需要哪些数据，不应把改判数当质量排名来回复。

**可填写 Prompt**

~~~text
以 {{冻结稿｜文件名和版本}} 与 {{报告｜附对应 REV 编号、完整审稿原文及页码}} 为准，只处理 {{本轮选定项｜编号和优先级}}。先判断意见是否适用本稿，再区分「稿内已有证据」「要复算或查原文」「要新增数据」「只需文字、图表或格式处理」。对研究项交证据、可复算结果和验收条件；保留未获支持的结果。不要直接改稿。最后列出各项应交给谁、交什么文件，标明不需或无法执行的理由。
~~~
